## 開発時に元映像で確認した頭出し

『冒険家エリオットの千年物語』Part5 では、ロード後に操作画面が復帰するのが `1:09`。次の暗転が始まる `1:13` が場所紹介の導入に当たる。導入前の移動目標と、`2:25` から画面左上に表示される「北の白楼」「1階」で場所名を確かめた。

同じ録画で別の会話から酒場の店主への暗転が始まるのが `40:10`。店主の依頼が `40:13` から読み取れ、`42:02` の依頼票に「我が家の家訓」が表示されている。これらは開始秒と根拠秒を分けて検証するため、Issueに明示されていた箇所を開発時に調べたもの。

無音声の冒頭165秒と、元録画の `39:25` からの180秒を通常のCLIで処理した。生成結果を元の再生位置で示す。

| 生成された見出し | 開始 | 根拠画面 |
| --- | ---: | ---: |
| プレイ再開 | 1:09 | 1:09 |
| 北の白楼の紹介 | 1:13 | 2:25 |
| 依頼「我が家の家訓」 | 40:10 | 42:02 |

この冒頭クリップには、既に会話している主人公を改めて「登場」とした行も含まれた。既知区間での確認と全編の検出成績は別々に集計する。

同じ3件で採点方法も点検した。ローカルの映像モデルは、再開と依頼を原票の言い換えに対応付けた。場所紹介では、その後に表示される移動目標を別の場所と解釈し、正しい生成行を取りこぼした。再開の映像に架空の「釣り大会で優勝」という見出しを付けた対照は未対応と判定した。全編の採点では、許容範囲に候補がある拾い漏れや、辞書の有無で判定が逆転した候補を元映像で再確認できるよう、行ごとに根拠と判定の履歴を残す。

作品名と録画の2引数で、固有名詞と進行段階も確認した。同じMacのQwen3-VL-8BとApple Visionの日本語OCRを使った。

- 『ユミアのアトリエ』では、同じ「アルボール植物園へ」の目標で次の行動が変わる2段階を区別できた。地図を操作中に出ていた5件の移動候補は一覧から除かれ、フィールドに復帰した時刻が残った。開発中には素材の取得を敵との遭遇と誤り、別の人物に画面に出ていないボス名を付けた。修正後に同じクリップを処理すると、素材は画面に出た名前で取得として記録され、裏付けのないボス名は出力されなかった。
- 『冒険家エリオット』では、接敵から再戦までの501時点を元録画で調べた。会話の話者名と、登場演出やHPゲージに表示されたボスの称号を区別した。再戦の短区間では「開闢の憎悪カイフリード」の称号付きの戦闘開始とガードを拾い、通常攻撃の3行は1行にまとまった。発話を能力の変化と解釈した行は、数値や状態が変わったことを画面から確認できなかった。

## 開発用7作品で確認した誤り

`5568d9a` の音声・辞書ありの出力は、見本153件中52件と、連続調査で追加した54件中7件に対応した。対応した59件のうち41件は、出来事の開始許容範囲を外れた。『ステラーブレイド』ではカヤがトランクの回収に礼を言う場面を拾えたが、カヤに話しかけた時点より約40秒遅かった。

『AI：ソムニウムファイル』では場所カードから「中央病院」や「無国籍料理 ブラフマン」への移動を拾えた一方、「代谷木公園」を「代谷市公園」と書き、表示途中の「2月12日」を「2月1日」と読んだ。『ゼルダの伝説』ではドラッドがクーシャに感謝する会話を拾ったが、語尾の「ゾラ」を相手の名前として使った。7作品の同じ出来事・同じ欄で辞書の有無を比べると、誤表記が正しくなった件数と、その逆の件数は各0件だった。

採点側の映像モデルにも、同じ名前や操作が再び出たときに別の場面と取り違える例があった。モデルが対応を付けた候補や、開始・根拠時刻の近くに残った候補は、生成行と原票の両方の再生位置を照合した。たとえば『ドラゴンクエストII』の勝利画面では、直前の戦闘ログから敵の種類を確かめて別の群れとの勝利を除いた。この照合はAIによるもので、人による二重採点は実施していない。
